# 0:16-0:38 变化一：入口从功能变成目标

## 核心观点

传统软件的基本单位是功能，AI Native 的基本单位是目标。

差别不是“多了一个 AI 按钮”，而是用户不再负责拆步骤，软件开始围绕目标组织步骤。

## 视觉逻辑

用修图这个低门槛例子讲清楚：

- 传统软件：用户必须知道用哪些功能
- AI Native：用户表达目标，系统自动组织能力

观众看完应明白：

`功能入口 -> 目标入口`

## 建议画面流程

1. 承接上一段判断句，出现“完成工作的责任，到底还在不在你身上？”
2. 画面左右分屏。
3. 左边是传统修图路径：选区域、选工具、调参数、修边缘、看结果。
4. 右边是 AI Native 路径：用户输入“把这个人去掉”。
5. 目标进入 AI Core，AI Core 调用识别、填充、检查能力。
6. 最终以结论字卡收束：`功能入口 -> 目标入口`。

## 建议画面

左侧传统路径：

- 多个功能节点横向排列或阶梯排列
- 每个节点之间由用户手动连接
- 节点略显分散，表现“用户在拼流程”

节点：

- `选区域`
- `选工具`
- `调参数`
- `修边缘`
- `看结果`

右侧 AI Native 路径：

- 一个目标输入框或目标节点
- 中央 AI Core
- 三个后台能力节点围绕 AI Core

节点：

- `识别对象`
- `补全背景`
- `检查结果`

屏幕关键词：

```text
功能入口 -> 目标入口
```

## 旁白

```text
真正的 AI Native，关键要看一点：
完成工作的责任，到底还在不在你身上。

比如修图。
传统软件要你选区域、选工具、调参数、修边缘、看结果。

AI Native 的路径是：
你说“把这个人去掉”，软件自己识别对象、补背景、检查结果。

差别不在多了 AI 填充，而是基本单位变了：
传统软件卖功能，AI Native 接目标。
```
