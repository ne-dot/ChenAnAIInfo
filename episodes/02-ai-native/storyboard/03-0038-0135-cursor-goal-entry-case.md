# 0:38-1:35 Cursor 案例：目标放到了入口

## 核心观点

Cursor 值得拆，不是因为它会写代码，而是因为它把“目标”放进了主入口。

用户不需要先指定文件、方案和步骤，而是给出结果要求；系统负责组织工作流。

## 视觉逻辑

这一段承担“真实产品证明”的作用。

先对比旧模式：

- AI 像侧边栏助手
- 它能回答问题
- 但用户仍然自己找文件、改代码、验证

再展示新模式：

- 用户输入一句目标
- Agent 自动拆任务、读文件、改代码、跑命令、验证结果

最终落到责任转移：

`过去是用户拼流程，现在是系统组织流程。`

## 建议画面流程

1. 旧 IDE AI 侧边栏出现，AI 在旁边回答。
2. 主界面中的文件树、代码区、终端、浏览器验证仍然分散，连接线回到用户身上。
3. Cursor/Agent 目标输入出现。
4. 用户输入一句完整目标：修复筛选刷新丢失，并完成本地验证。
5. Agent 自动列 todo。
6. 工作流依次点亮：找文件、改代码、跑命令、浏览器验证。
7. 画面收束到任务状态：`Done` 或 `任务完成了吗？`

## 建议画面

旧模式画面：

- 左侧代码编辑器
- 右侧 AI 侧边栏
- 用户任务节点在下方
- 多条手动路径连接到文件树、代码、终端、浏览器

新模式画面：

- 中央目标输入框
- 中央/上方 Agent Core
- 四个工作节点围绕展开

节点：

- `列 todo`
- `读文件`
- `改代码`
- `跑命令`
- `验证结果`

屏幕输入文本：

```text
修复筛选刷新丢失
并完成本地验证
```

结论字卡：

```text
用户给结果
系统组织流程
```

## 旁白

```text
Cursor 是一个值得学习拆解的软件产品。
不只是因为它会写代码，更关键的是，它把入口改了。

在很多 IDE 里，AI 像侧边栏助手。
你问它问题，它可以回答。
但接下来，还是你自己找文件、判断方案、改代码、再去验证。

Cursor 更像是把目标放到了入口。
你只需要说：“修复筛选刷新丢失，并完成本地验证。”

它会去找相关文件，列出步骤，修改代码，运行命令，再检查结果。

你提出的是目标。
Cursor 交付的是结果。

这就是责任转移：
过去是用户自己拼流程。
现在是系统组织流程，用户负责提出目标，并验收结果。
```
