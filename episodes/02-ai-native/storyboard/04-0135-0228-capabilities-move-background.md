# 1:35-2:28 第二个变化：能力从前台按钮变成后台执行

## 核心观点

AI Native 不只是把输入框换成自然语言，而是把一组能力接入主流程。

这组能力包括：

- 理解目标
- 读取上下文
- 调用工具
- 推进执行

## 视觉逻辑

不要做成四张 PPT 字卡。要做成“前台一句话，后台一整套流程”的机制动画。

观众应看到：

- 前台只有一句目标
- 后台有多个系统能力在协作
- 用户不用手动调用每个功能

最终结论：

`越好的产品，越是前台简单，后台复杂。`

## 建议画面流程

1. 前台出现一句话：`修复这个 Bug`。
2. 镜头轻微后拉，显示这句话背后连接到 AI Core。
3. AI Core 周围展开四个能力节点。
4. 四个能力依次点亮，每次只突出一个。
5. 每个能力点亮时，背景闪回 Cursor 案例中的对应工作画面。
6. 最后四个能力汇入一条主路径，输出结果。

## 建议画面

主结构：

- 上方：用户目标输入
- 中央：AI Core
- 四周：四个能力节点
- 下方：结果状态 / 验证通过

四能力节点：

- `理解目标`
- `读取上下文`
- `调用工具`
- `推进执行`

对应闪回素材：

- 理解目标：目标文本被解析成意图、约束、验收标准
- 读取上下文：文件树 / 代码片段 / 路由状态 / 终端报错
- 调用工具：编辑器 / 终端 / 浏览器 / diff
- 推进执行：todo 状态推进，失败后继续迭代

屏幕关键词：

```text
前台一句话
后台一整套流程
```

结论字卡：

```text
前台简单
后台复杂
```

## 旁白

```text
但 Cursor 不只是把输入框换成自然语言。
它背后真正变化的是：一组能力进入了主流程。

第一，理解目标。
你说的是“筛选刷新后不能丢”，不是“请修改某个 state”。

第二，读取上下文。
它要知道项目结构、当前文件、相关组件、路由状态、终端报错。

第三，调用工具。
它不能只告诉你怎么做，还要能改文件、跑命令、看结果。

第四，推进执行。
如果刷新后还是丢，它要继续查、继续改、继续验证。

所以越好的产品，越是前台简单，后台复杂。
```

## 动画

动画编号：

```text
A09 四能力总览：能力进入后台
A10 理解目标
A11 读取上下文
A12 调用工具
A13 推进执行
```

推荐运动方式：

- Assemble：四能力从后台展开
- Draw：AI Core 到各能力节点的圆角路径
- Flow：能力之间有主流程光点流动
- Step Highlight：每个能力依次成为唯一视觉焦点
- Camera Pull Out：从一句话拉出后台系统

## 素材类型

- 生成动画：AI Core、能力节点、后台路径、状态推进
- 可复用 Cursor 段的界面片段作为背景闪回
- 不需要额外真实网络素材

## 剪辑备注

四个能力每个约 10-12 秒。每次只突出一个能力，避免四个节点同时发光。字幕可以跟随能力节点出现，不要堆长句。
